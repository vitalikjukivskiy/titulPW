# Поле чудес — live

Сайт для розіграшу під час стріму. Оригінальний 60-секундний барабан збережено в `public/wheel.html`. Гравці записуються на головній сторінці, бачать обертання барабана під час раунду та спільний результат на всіх пристроях.

## Як провести розіграш

1. Надішліть гравцям адресу головної сторінки. Вони вказують ігровий нік.
2. Ведучий відкриває `/wheel.html`, вводить код ведучого і бачить спільний список.
3. Для завершення набору натискає «Закрити запис», потім «Крутіть барабан».
4. Колесо обертається 60 секунд у ведучого й глядачів. Глядач, який відкрив сторінку посеред раунду, бачить поточний етап обертання. Сервер публікує результат і зберігає історію, навіть коли вікно ведучого закриється.
5. Для наступного раунду ведучий натискає «Відкрити запис». Потрібного переможця зі списку можна прибрати вручну.
6. У пульті ведучого кнопка «Видалити всіх учасників» очищає спільний список після явного підтвердження. Під час крутки та для порожнього списку вона недоступна. Історія результатів і стан реєстрації зберігаються; після очищення гравці можуть записатися знову, коли запис відкритий.

Один браузер може подати одну заявку. Повторний ігровий нік також не приймається. Нік не підтверджує особу персонажа: перед видачею призу ведучому слід звірити переможця в грі. Одночасно підтримується до 100 учасників. Старі результати зберігаються, а сторінка показує 50 останніх.

## Налаштування

Розгортання використовує Cloudflare D1 через Sites. `.openai/hosting.json` оголошує прив’язку `DB`; міграції лежать у `drizzle/`. Серверні секрети `ADMIN_PIN` та `SESSION_SECRET` задаються лише в конфігурації розгортання, не в коді чи GitHub. Ведучий входить за кодом через HTTPS; браузер отримує HttpOnly cookie на 12 годин.

Для локального запуску потрібні Node.js 22+, `npm ci`, `npm run db:generate` при зміні схеми, `npm run dev`. Для розгортання застосуйте SQL-міграції D1 і налаштуйте зазначені змінні.

## Перевірки очищення списку

Серверні тести: `node --test scripts/test-admin-action.mjs` (Node.js 24+). Вони виконують справжні API handlers з окремою SQLite у пам’яті й тестовими секретами, без доступу до production.

Браузерні тести: `node scripts/test-admin-ui.mjs`. Потрібен доступний пакет `playwright` і його Chromium; за потреби `PLAYWRIGHT_MODULE` задає шлях до встановленого пакета, а `PLAYWRIGHT_BROWSER` — до браузера. Тест піднімає локальний сервер із тестовою БД, перевіряє адмінку та зберігає скриншоти в ігнорованому `outputs/`.

## Donatello: квитки за підтримку

Бонус за 200 тапів замінено квитками. Базова участь лишається безкоштовною:
один квиток на зареєстрованого учасника. Сума підтверджених UAH-донатів за
раунд дає ще один квиток за кожні 50 грн, максимум 10 разом із базовим.
Наприклад, 25 + 25 грн дають один додатковий квиток. Надлишок понад ліміт
не переноситься. Кожен квиток має однакову ймовірність; сектор учасника
пропорційний кількості його квитків. Приз і правила його отримання оголошує ведучий.

Посилання автора: https://donatello.to/general_yogik.
Параметри чернетки задано у `lib/tickets.ts`: `TICKET_PRICE_MINOR` (копійки)
та `MAX_TICKETS`. Змінювати їх слід до початку збору донатів на раунд.

### Підключення

1. Застосувати нову міграцію `0002_donatello_tickets.sql` разом із кодом.
   Sites застосовує її під час публікації. Старі міграції не змінювати.
2. Додати серверний секрет `DONATELLO_CALLBACK_KEY`: випадковий ключ
   щонайменше з 32 символів, не API-токен віджетів. Не комітити його.
3. У Donatello → API → **Колбеки**, обрати `POST`, вказати URL
   `https://pole-chudes-live.vitalik-juk.chatgpt.site/api/donatello/callback`
   та той самий ключ у полі **API Key**. Увімкнути колбеки.
   Вкладка «Вебхуки» імпортує донати *до* Donatello і для цієї інтеграції не потрібна.
4. Перевірити тестове повідомлення Donatello та журнал колбеків. Повідомлення
   без коду учасника не додає квитків. Реальний платіж перевіряти окремо:
   автоматизовані тести не проводять платежів.

Офіційний формат перевірено 10.11.2026 у кабінеті:
https://donatello.to/panel/doc-api?tab=callbacks.
Donatello надсилає `X-Key` і JSON із `pubId`, `source`, `amount`, `currency`,
`message`, `createdAt` (Unix seconds). Секрет перевіряється на сервері.
`pubId` унікальний у журналі, повторна доставка не змінює баланс.
Підписки, імпортовані донати й валюти, відмінні від UAH, не зараховуються.

Учасник копіює приватний код `PW-…` зі своєї сторінки у повідомлення донату.
Сервер звіряє саме код, а не довільне ім'я платника. Коди інших учасників,
ключі та повідомлення донаторів не віддаються у публічному API.
Для старих учасників код створюється при їх поверненні, без масового backfill.

Донати, доставлені після старту колеса, зараховуються **до наступного раунду**,
незалежно від часу оплати. Уже запущений розіграш використовує незмінний
знімок квитків. Наступний раунд починає новий облік донатів; базовий квиток
лишається, поки учасник є у списку. Учасників із донатами на майбутній раунд
не можна видалити одинично або кнопкою очищення списку.

У пульті ведучого є журнал останніх 50 донатів. Записи без правильного коду
позначено для ручної звірки: вони не додають шансів автоматично. Поточна версія
не має автоматичного повернення, ручного переназначення донату або імпорту
платежів, пропущених до ввімкнення колбеків. Старі результати, вбудований
YouTube-стрім і керування реєстрацією збережені. Перевірку Telegram/Twitch
ця зміна не додає.

### Перевірка інтеграції

`npm test` (Node.js 22.18+ або 24+) виконує API handlers із SQLite у пам'яті:
секрет, повторні доставки, округлення, ліміт, одночасний донат і старт,
пізні платежі, приватність кодів, стару історію, стрім і безпечне очищення.
`npx tsc --noEmit` перевіряє типи, `npm run build` — production-збірку.
Старі `scripts/test-tap-boost.mjs` описують попередню механіку і більше не є
перевіркою актуальних шансів. Маршрут `/api/tap` повертає 410 для старих вкладок.
